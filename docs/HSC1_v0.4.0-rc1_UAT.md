# HSC1 新版真实数据测试指南（已被替代）

当前候选请使用 `HSC1_v0.4.0-rc4_UAT.md`。本文件仅保留为较早候选的历史记录，不再作为操作依据。

这份指南只做一件事：用当前开发版新建一个 HSC1 项目，并完成从参考段校准到导出的检查。

## 开始前

直接运行：

```text
lifms_annotation_windows_source\dist\LMAStudio\LMAStudio.exe
```

调试 `dist` 目录即可；ZIP 和安装包留到最终分发时再测。先关闭其他 LMA Studio 窗口。

项目输出目录可以用：

```text
E:\path\to\scMetab\HSC1
```

但这个 `HSC1` 必须尚不存在或是空目录。若里面已有旧项目或人工标注，请保留它并改用 `HSC1_v2` 等新目录，不要覆盖。

原始数据位于 `HSC1_data`。它只作为输入，不能作为项目输出目录，也不应被修改。

## 第一步：填写新项目

点击“新建项目”，选择“外部引用”，然后填写：

| 项目 | 设置 |
|---|---|
| 项目目录 | 新的空目录，例如 `scMetab\HSC1` |
| LIF 峰检测 | `v2 自适应 core + weak（推荐）` |
| G1 | Green；科学身份 `LSK`；文件 `HSC1_data\Lin-_LSK\G1.CSV` |
| G2 | Green；科学身份 `Lin−`；文件 `HSC1_data\Lin-_LSK\G2.CSV` |
| MS | `HSC1_data\Lin-_LSK.txt` |
| 事件坐标 CSV | `HSC1_data\HSC-Lin-LSK-20260809-After-Batch-Correction.csv` |
| 事件标注起点 | `24 min` |
| 后段 QC | `disabled（不巡检）` |

不要添加 R1/R2：HSC1 实验没有实际使用它们。G1/G2 都选 Green 后，软件会自动把它们放到同一个共享 Green 时间轴，不需要填写内部轴名。

事件坐标 CSV 只需包含 `scan_start_time`、`UMAP1`、`UMAP2`。表中可以同时保留 `CellNumber`、`batch`、`Type` 等其他列；软件会找到所需三列并忽略其余列。

## 第二步：不知道参考段边界也可以继续

推荐先点击“分析已选 LIF 并建议窗口”。软件会根据当前所选 LIF 回填 G1/LSK 和 G2/Lin− 的建议范围，但不会替你确认科学边界。

如果建议失败，或你仍不确定边界，也可以保留未确认状态，点击“生成草稿并进入项目”。按钮应立即变成“正在创建… Ns”，持续显示等待时间；8 GB MS 文件处理较慢，请勿重复点击。

草稿项目只能查看前段原始轨迹。此时校准、后段 delta、冻结和事件标注都保持锁定，这是正常门禁。

进入项目后：

1. 在原始时间轴查看 G1 在前、G2 在后的参考峰群。
2. 打开“配置”，调整每段开始和结束时间。
3. 确认两段顺序正确、互不重叠后，分别勾选“边界已确认”。
4. 保存配置，随后再进行校准。

本批数据的只读峰形建议曾落在 G1 约 `1.9–8.3 min`、G2 约 `13.1–20.0 min`，但这只是本项目的可编辑建议，不是全局常量。

## 第三步：理解 core 与 weak 峰

新版 v2 不再把旧 V3 的单一全局阈值当成唯一检测器：

- `core` 是旧 V3 高特异性峰，仍用于自动校准、delta 和细胞候选；
- `weak` 使用局部稳健噪声、同通道 core 峰学到的脉冲形态和经验宽度进行补充；
- weak 默认隐藏。勾选顶部“显示 weak 弱峰”后才显示为空心/虚线标记；
- weak 只供人工检查，不参与自动匹配，也不能训练时间模型；
- 在事件标注阶段，若人工确认 weak LIF 峰与 MS event 的配对，该人工结果可以正常导出。

旧项目缺少这套检测配置时会按 v1 只读兼容打开。不能在旧项目配置页直接切换 v1/v2，因为旧 parquet 峰表已经由原检测器生成。要使用 v2，必须新建项目或复制原始输入后重跑中间表；已有人工标注不会被软件静默删除或迁移。

只读审计曾得到以下诊断值：G1 为 `1002 core + 71 weak`，G2 为 `323 core + 85 weak`。R1 只有 1 个贴阈值孤点，R2 有 17 个分散孤点，二者都没有满足形态学习门禁，因此没有新增 weak。这些数字用于发现明显回归，不是要求新项目强行达到的目标。

事件坐标 CSV 的 971 行也不能作为 LIF 峰数的调参目标：一个细胞事件可能缺少可见 LIF 峰，LIF 也可能包含参考峰、弱峰或未进入最终事件表的脉冲。应核对时间匹配、残差和人工证据，而不是把两个行数硬凑相等。

## 第四步：完成前段校准

边界全部确认后：

1. 在“前段参考校准”逐段查看并接受可信 anchor。
2. 候选连线必须保持时间顺序，不应出现前后交叉的配对。临近峰证据不唯一时，应显示歧义并留给人工选择。
3. 点击“用已接受参考 anchors 预览重算”，查看内点、冲突和残差。
4. 点击“应用 QC 对齐（按物理轴）”。HSC1 应只有一个共享 Green 轴平移。
5. 进入“无标签后段 delta”，从项目参数 `24 min` 开始估计。
6. 证据合理后，点击“确认并冻结无标签 delta”。

若修改已冻结模型依赖的参考段、事件起点或其他时间参数，软件应明确提示失效；旧人工标注保留为历史，但必须重算并重新冻结，不能继续静默使用旧结果。

## 第五步：标注、UMAP 与导出

冻结后进入“事件标注 / QC 巡检”。HSC1 的后段 QC 为 disabled，因此这里应只有细胞候选。

若连线太密，把顶部“窗口宽度 (min)”改为 `0.25`、`0.5` 或 `1.0`，按 Enter 或点击“显示窗口”。左右箭头会按当前宽度移动；这个显示宽度不会改变项目的 delta 取证范围。

若 G1 和 G2 都指向同一个 MS event，必须人工选择 LSK 或 Lin−，不能同时接受。再检查 Track 与 UMAP 的点击定位和接受/撤销状态是否双向同步。

完成后点击“导出 Cell/QC 主 CSV”。主 CSV 固定为精简的 16 列，便于后续按 cell 读取；前段 anchor、模型 hash、歧义详情和完整审计历史保留在项目 SQLite 中。`Type` 来自接受的 LIF 通道科学身份，不会复制事件坐标源表中的作者标签。

## 报错时保留什么

不要删除失败项目。请记录：

- 点击的按钮和完整报错；
- 当时是否为草稿、边界是否全部确认；
- 当前窗口的时间范围和时间轴模式；
- 是否勾选“显示 weak 弱峰”；
- `HSC1\annotation_app\annotations\annotation.sqlite` 是否已生成。

截图时尽量同时包含顶部控件、通道名、峰点和候选连线。
