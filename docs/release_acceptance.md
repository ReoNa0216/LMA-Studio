# LMA Studio 当前版本验收指南

本指南用于当前 v0.4.12 桌面版本。版本历史由 Git tag 和 `README_RELEASE.md` 保存，不再为每个补丁版本复制一份 UAT 文档。

## 安全边界

1. 先关闭所有 LMA Studio 窗口。
2. 完整复制待验收项目，在副本上测试写操作；不要修改原项目或任何原始实验数据目录。
3. 新建项目必须选择一个不存在或为空的目录。
4. Windows 和 macOS 包应解压到独立目录，不要覆盖仍在使用的旧包。

项目最外层目录可以整体移动或改名。不要只移动内部 parquet、SQLite 或事件坐标表，也不要在软件运行时复制项目。

## 现有项目兼容

用当前版本打开一个 v0.4.0-v0.4.11 当前峰识别标准项目的完整副本，确认：

- 既有标注、待审关系、冻结时间模型、Track、UMAP 和导出均正常；
- 软件按 `lifms_project.json` 中的路径打开项目，不整理或迁移旧目录；
- 打开项目不会重新运行峰识别或 MS event 识别；
- 根目录整体改名后仍能打开；
- 已停用峰识别标准的项目在任何写入前被拒绝，并提示从原始输入在新空目录重建。

## 原始 MS 新建项目的事件绑定

用项目副本或新的空目录执行真实输入导入，确认：

- 事件 CSV 必须包含 `scan_start_time`；`UMAP1`/`UMAP2` 可选且必须成对提供；每一行都必须唯一绑定到一个 MS event，未匹配或歧义行会让项目原子创建失败，不会留下半项目；
- 绑定失败时，新建窗口显示已匹配、未匹配、歧义和复用冲突的逐行汇总，并可下载 UTF-8 CSV；报告包含 CSV 行号、时间、原因、候选/最近事件和时间差，但不包含 `Type`、`batch`、`CellNumber` 或作者标签；
- 下载报告后确认目标项目目录仍不存在，修正原始事件名单或检查 MS 峰证据后，再在空目录重试；不要通过删除名单行来绕过门禁；
- 软件优先使用严格 apex 时间容差；新项目只有没有 apex 命中时，才允许使用距 apex 不超过 0.25 秒的唯一局部峰形关系；
- 两个 support 区间重叠时仍视为歧义，不能靠放宽全局时间容差自动猜测；
- 自动 MS760 core 仍使用 ±12 ppm 和既有阈值。只有名单行缺少 core event 时，零膨胀信号上的独立 ±15 ppm 审核通道才可补入一个同时满足精确名单时间、局部极大值、峰距和局部起伏的事件；强证据仍使用 robust upper-fence，仅人工复核层可使用安静背景局部峰的第 90 百分位门槛；
- 补入事件只能人工 Cell pair，不得进入前段校准、时间差、后段 QC、自动 Cell 候选或模型训练；
- MS 阈值完全来自原始 PC34 信号及其背景分布，不读取 CSV 行数、`Type`、`batch`、CellNumber 或其他身份标签；
- 已有 v0.4.0–v0.4.10 项目仅按 manifest 打开既有事件表，schema-1 项目按原 half-height 语义回放，不会因升级而重新运行 MS event 识别。

## 人工 Cell pair 待审

1. 在 `Events / QC` 中选择一个可用于细胞标注的 LIF 峰和一个坐标 CSV 内的 MS760 event。
2. 点击 `Save pending`，或在未编辑输入框且无弹窗时按 `D`。
3. 关系应以待审样式保存；切换窗口或重新打开项目后仍可见。
4. 待审关系不进入主 CSV 或 UMAP 分类，不占用 MS event，也不参与模型训练。
5. 在审查区接受后，它才进入 CSV/UMAP，并按既有互斥规则占用该 event；拒绝后保留审计记录。

## macOS 原生 UMAP 窗口

在 Apple Silicon Mac 上完成以下鼠标级检查：

1. 首次点击 `UMAP`，应出现独立的 LMA Studio 原生窗口，而不是 Chrome/Safari；主标注窗口继续可操作。
2. UMAP 仍打开时再次点击，应唤回同一窗口，不创建重复窗口。
3. 关闭 UMAP 后再次点击，应创建一个新的原生窗口。
4. 页面不应出现“请求不是从本机应用发出”或“没有可用的事件 UMAP”等由外部浏览器上下文引起的错误。
5. Track 双向定位、MS760 时间查询和坐标切换应与 Windows 一致。

## UMAP 坐标切换

1. 在项目副本的 `配置 > UMAP coordinates` 选择另一份包含 `scan_start_time`、`UMAP1`、`UMAP2` 的 CSV；其他列可以保留。
2. 点击 `Validate & switch`。新 CSV 必须映射到完全相同的 MS-event 集合。
3. 成功后，既有标注数量、峰表和冻结时间模型不变；已打开的 UMAP 刷新，下一次主 CSV 导出使用新坐标。
4. 软件使用项目内规范化副本，因此成功切换后移动外部源 CSV 不应影响项目。
5. 缺少或新增 event 的 CSV 必须被拒绝，且原坐标继续有效。

## UMAP 时间查询与布局

- 查询框应完整显示类似 `e.g. 49.001` 的提示；窄窗口下控件自动换行，不溢出工具栏。
- 输入 MS760 时间后，命中点显示红色轮廓；缩放和平移保持不变；清除查询后轮廓消失。
- 在 Track 双击事件坐标表内的 MS760 峰，UMAP 应打开或唤回并用红圈标出同一 `ms_event_id`，但不缩放、不平移。
- 按 `S` 开关 `Select peaks`；在 `Events > Cell pair` 中按 `A` 执行 `Save pair`、按 `D` 执行 `Save pending`。输入框、下拉框和弹窗中不得误触发。
- Track 与 UMAP 中已接受细胞的 G1/G2/R1/R2 颜色必须一致；MS760、MS782 与四个 LIF 通道应保持清晰可辨。切换到旧项目不应改写其 manifest、SQLite 或中间表。
- 查询只定位点，不修改标注。
- 正式标注段没有当前有效 QC 时，UMAP 不显示 QC 图例。

## 垂直参考线与 G2 颜色

- 在 Calibration、MS Δt 和 Events / QC 三个阶段分别勾选 `Reference line`；红色竖线应贯通当前全部通道，并随鼠标横向移动。
- 在图内空白处单击后竖线固定；峰点、弱峰命中区或候选连线的原有点击动作不得被抢占。再次单击竖线后恢复跟随。
- 固定后按左右键应移动一个显示像素，按住 `Shift` 时移动十个显示像素；光标位于输入框、下拉框、按钮或弹窗时不得误移动。
- 切换窗口后参考线回到新窗口中部并恢复跟随；勾选、移动或固定参考线不得改变候选、人工标注、时间模型或项目文件。
- G2 在 Track 与 UMAP 中都应显示为同一金黄色，并与 G1 紫色、R1 青色和 R2 洋红色清晰区分；旧项目无需迁移。

## Calibration 物理时间轴微调

1. 在含 Green 与 Red 两条物理时间轴的项目副本中进入 `Calibration`，点击 `微调 LIF 时间轴`。
2. 确认界面只提供“绿色轴 G1/G2”和“红色轴 R1/R2”，不会为单个通道分别提供滑块；标签与数值不得挤压、遮挡或意外换行，数值表示 LIF 相对 MS 的总平移秒数。
3. 拖动整行滑条，或使用 `−0.25 sec` / `+0.25 sec` 调整：数值、Track 信号及其时间刻度应连续跟随，不出现逐步等待后端刷新的停顿。G1/G2 必须一起移动，R1/R2 必须一起移动，Green 与 Red 互不牵连，MS760/MS782 始终不移动。
4. 调整时图窗应实时预览，但候选审核和人工连线暂时隐藏；点击 `取消预览` 后轨迹恢复，项目文件与标注均不变化。
5. 点击 `应用微调` 时必须明确提示下游 MS 时间差需要重算、已有人工标注会保留。应用后重新打开项目，轴平移仍生效，后段时间模型为待重算草稿。
6. 用一个 v0.4.0-v0.4.11 项目副本重复打开、预览和取消操作，确认无需重建项目或迁移目录。
7. 在 `MS Δt` 阶段拖动时间差滑条并点击 `±0.25 sec`，确认数字和两条 MS Track 同样即时跟随；只有点击锁定时才等待后端校验。

## 主 CSV

导出 `Cell/QC 主 CSV` 后确认：

- 仍为固定的 16 列事件表；
- 坐标表中的每个 event 恰好一行；
- 未标注 event 使用 `Type=unknown`，人工待审关系也仍按未接受状态导出；
- 前段 QC anchor 不混入主事件表；
- 内部 hash、歧义 payload 和模型审计只留在 SQLite。

## 分享项目

关闭 LMA Studio 后，压缩整个项目根目录。接收方安装相同或更新版本，完整解压后选择项目根目录即可查看、继续标注和导出；根目录改名不影响打开。外部原始输入模式的项目可以正常分享运行时结果，但若接收方要从头重跑预处理，仍需另行取得原始 LIF/MS 文件。
