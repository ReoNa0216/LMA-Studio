# 项目 ZIP 与事件传递

入口：顶部“分享项目”。选择项目文件夹以外的保存位置，应用创建新的 `项目名-share-随机标识.zip`。
接收者解压后，通过同一 Studio 的“打开项目”选择解压得到的项目文件夹。

| 导出 | 用途 | 内容 |
| --- | --- | --- |
| 分析结果 ZIP（MS） | 独立查看事件表和分析矩阵 | 事件 CSV；可选当前有效矩阵及其完整 v2 事件证据 |
| LMA 事件包 ZIP（MS） | 正式导入 LMA | 当前代次全部状态的 v2 事件、交接校验记录和可选矩阵 |
| 分析结果 ZIP（LMA） | 使用带人工标签的分析数据 | 细胞/QC CSV、可选带标签 H5AD 及导出记录 |
| 打包分享项目（两 Studio） | 换电脑或给同事继续工作 | 当前项目目录，包括数据、标注、模型、绑定和已有历史文件 |

MS“传给 LMA Studio”生成独立交接 ZIP；LMA 新建项目选择“LMA 事件包 ZIP（可含矩阵）”，并提供对应 MS raw 和 LIF 输入，不重新调用 MS caller。分析 ZIP 不用于交接。新建界面不再并列文件夹入口，已有文件夹来源的项目仍可打开。
事件包不包含完整操作日志和退休代次；继续原项目审阅应分享项目 ZIP。

## 保存边界

- ZIP 保留项目内现有文件，包括已经放在项目内的原始文件。不会沿清单中的外部 raw 引用寻找或复制大文件；需要重新分析时另行提供对应 raw。
- 排除任意层级 `__MACOSX`、`._*`、`.DS_Store`，不删除源目录中的这些文件。
- 仅活动审阅 SQLite 使用 online backup，包含已提交 WAL 内容。历史数据库可能有不可变哈希绑定，保持原始字节。
- 不增加审计行、不更改事件/标注/时间模型/绑定。SQLite 读取可能产生空 WAL/SHM 或改变 SHM 锁信息；这类临时读锁元数据不进入 ZIP，不代表科学内容写入。
- 不跟随文件链接或目录链接。目录不可读取、文件变更、并发审阅提交或数据库完整性失败均中止。
- 完整 ZIP 在同一目标卷的临时目录内完成，Windows 使用无覆盖 rename，macOS 使用 Darwin `RENAME_EXCL` 后发布。若目标卷不支持原子发布，明确失败，请改存本机目录；不降级为覆盖目标。
- 打包前可取消目录选择。写入期间需保持应用打开，当前没有中途取消按钮。

## 实现与验证入口

项目存储逻辑位于 `annotation_app/project_archive.py`，不进入科学 `flame-ms-core`。
API：`POST /api/share-project`，携带所选父目录、当前项目 ID 与根目录，沿用写入 token。应用串行化自身编辑，MS 的后台打包注册与范围更新在同一会话锁下互斥；另检查打包期间文件清单、非数据库文件属性及 SQLite data_version。
测试 `tests/test_project_archive.py` 覆盖 WAL、历史原字节、目录错误、写失败、并发修改、目标边界和不覆盖。
当前候选证据见父工作区 `studio-validation/validation.json`；用户验收、双平台 Release 完成后再同步共享交接。源码功能完成不等于用户 UAT 或 macOS 真机操作已通过。
